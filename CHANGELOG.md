# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/).

## [Unreleased]

### Added

- Added deterministic real-browser Playwright coverage for Phase 3 (3D) premoves (`test/browser/premove3d.spec.js`): with the 3D board active, an off-turn premove is selected and submitted on the WebGL board, confirmed by the server (status chip), and visualized (deep-blue confirmed squares, dashed system arrow, semi-transparent destination ghost); the opponent's move auto-executes it (owner-only feedback, private to the owner); cancellation via origin re-click, same-square right-click on the origin, and ESC; a right-drag ending on the premove origin still draws its annotation arrow and leaves the premove intact; promotion premove via the picker; reconnect restore; and annotation clear / identical-endpoint annotation never removing the 3D system arrow. Squares are addressed through new minimal, read-only, development/test-safe test hooks that expose renderer state only: `window.__testSquareScreenPos(file, rank)` (projects a square center to screen coordinates via the live camera), `window.__testPremove3D()` (shared premove value, selection, confirmed-square emissive fills, dashed system arrow), `window.__testPremoveGhost3D()` (destination ghost), and `window.__testAnnotationArrows3D()` (annotation arrow count).
- Added premove localization and owner-only feedback: all five locales now carry the full premove key set (`premove.set`, `premove.played`, `premove.discarded`, `premove.cancelled`, `premove.status`). On the private server premove confirmation the owner sees a short localized "Premove set" toast plus one soft pickup sound; when a stored premove executes, only the owner (`msg.color === myRole`) gets a localized "Premove played" toast while every client keeps the ordinary move animation/sound exactly once (no duplicated move sound). Discards stay silent by default (lichess parity) or show the localized optional toast when enabled; server-side clears and user-initiated cancels stay silent. The premove status chip remains localized and refreshes on language change via `refreshI18n()`.
- Added server-side premove protocol groundwork with private per-color storage, permissive candidate validation, cancellation, reconnect restoration, and automatic execution through authoritative move validation.
- Added premove lifecycle cleanup: premoves are now cleared on every whole-game reset/terminal path (restart, FEN import, both-disconnected auto-reset, concede, accepted draw, claim draw, and move-induced game over) via `clearPremoves()`, and on single-owner seat paths (join reassignment, explicit leave, permanent seat release) via `clearPremove(color)`, which preserves the connected opponent's premove. A raw WebSocket disconnect does not clear a held seat's premove, so it is restored on reconnect within the hold window.
- Added off-turn premove interaction on the 2D board: selecting your own piece during the opponent's turn shows permissive premove candidate dots, and completing the selection sends a `premove` (the server decides execute-now vs store). A pawn premove to a promotion rank opens the existing promotion picker in atomic premove mode — the chosen piece is sent with the premove in one message, and a dismissed picker is inactive so a stale button activation can never send a promotion or premove.
- Added off-turn premove interaction on the 3D board: selecting your own piece during the opponent's turn — by click, drag, or touch — shows permissive premove candidate moves (computed with `getPremoveMoves` on a cloned board), and completing the selection sends a `premove` (the server decides execute-now vs store). A pawn premove to a promotion rank opens the promotion picker in atomic premove mode. Cancellation works from the 3D board as in 2D: re-clicking the confirmed premove's origin, a same-square right-click on the origin (which takes priority over the highlight gesture, while a right-click drag ending on the origin still draws its arrow), and the ESC key (which yields to any open menu/help/settings overlay).
- Added the dashed 3D premove arrow: a confirmed premove now renders as an independent dashed deep-royal-blue (0x1e5ac8) 3D arrow sourced directly from the premove state, separate from the mutable annotation arrow list — annotation clear/toggle/dedup (including identical endpoints) can never remove or hide it. The ribbon body is split into dash intervals along the existing arrow path (knight bending included) with a solid arrowhead, dynamic screen-space width updates, and full geometry/material disposal on replace, clear, and teardown (no resource accumulation).
- Added a semi-transparent destination ghost for confirmed premoves in both renderers: the 2D board draws a non-interactive ~0.5-opacity clone of the premoved piece on the destination square (reusing the piece SVG conventions, drawn above any piece already there so captures and friendly recaptures stay readable), and the 3D board draws a visual clone at the destination with an independently transparent material (opacity 0.45, `depthWrite: false`), a small vertical offset to avoid z-fighting, and raycasting disabled. The real origin piece is never moved or hidden, shared piece geometry/materials are never mutated or disposed by ghost cleanup, and the ghost updates and cleans up across confirm/restore/replace/clear, board flip, piece/model-set rebuilds, and state updates without duplicate nodes. Spectators and opponents see nothing (premove state is private to its owner).
- Added persisted premove settings: "Enable premoves" defaults on and cancels any pending premove when switched off; "Notify when premove is discarded" defaults off and controls the optional owner toast. Disabled clients reject a racing confirmation and cancel a pending premove restored by reconnect. The localized help overlay now documents queueing, replacement, visuals, cancellation gestures, promotion choice, and both settings; the README and architecture protocol documentation describe the released feature.
- Added a live evaluation bar powered by the existing Stockfish connection: the server evaluates the position after every move, restart, and FEN import — and evaluates the starting position on the first client connection so the bar shows a value immediately (spawning the engine on demand) — and broadcasts an `evaluation` message (centipawns, normalized to White's perspective, positive = white) that is also included in every state message. Transient positions the computer is about to change are skipped so the evaluation never delays the computer's move. Desktop shows a vertical bar on the left edge (white at bottom) with a slider marker and +/- score label (e.g. `+1.25`, `M`); mobile portrait shows a wide horizontal bar at the bottom (clearing the camera buttons), and mobile landscape shows a vertical bar on the left edge. The bar renders neutral (50%) until the first evaluation arrives, resets to neutral when the game ends, and degrades gracefully when the engine is unavailable.
- Added comprehensive full-browser Playwright E2E coverage spanning join, moves, game-over, camera controls, and mobile flows.
- Added shared localization framework (`shared/i18n.mjs`, `shared/locales/*.mjs`). All ~150 user-facing strings are resolved via `t(key, params?)` lookups. The server sends machine-readable keys (e.g., `game.checkmate_white`, `error.not_your_turn`) instead of display strings, keeping it locale-agnostic. Static HTML strings use `data-i18n`/`data-i18n-aria-label`/`data-i18n-placeholder` attributes resolved on page load and live refresh.
- Added 4 new locales (Español, Français, Deutsch, 简体中文) with full translations verified against FIDE chess terminology sources. Language selector in Settings overlay with `localStorage` persistence and live UI refresh via `refreshI18n()` — no page reload required.
- Added Settings menu (accessible from the main menu) with mouse sensitivity slider, virtual joystick toggle, and dropdown selectors for 2D piece set and 3D model set. Selections persist in `localStorage` and apply in-place without a page reload.
- Added contributor guidance (`CONTRIBUTING.md`) and per-change changelog requirements (`AGENTS.md`).
- Added all 42 2D piece sets from Lichess (`client/files/pieces/2d/`) with consolidated license attribution in `client/files/LICENSE`.
- Added `jeu`, `low-poly`, `simple-classic`, and `afnafziger` 3D model sets (`client/files/pieces/3d/`) with CC0/public domain license, and made the 3D model set selectable via `getModelSet()`/`setModelSet()` in `client/pieces.js`. Default is `simple-classic`.
- Added `samurai` 3D model set (`client/files/pieces/3d/samurai/`) converted from FBX source ("Samurai chess" by 3DWorkbench, CC BY 4.0), decimated to ~712 KB total.
- Added `ornate` 3D model set (`client/files/pieces/3d/ornate/`) extracted from GLB source ("Ornate Golden Chess Pieces" by iGauravRajput, CC BY 4.0), decimated to ~986 KB total.
- Added `scrollsaw` 3D model set (`client/files/pieces/3d/scrollsaw/`) converted from FBX source ("ScrollSaw Chess Set" by trinityscsp, CC BY 4.0), topology-preserved, oriented Y-up, and reduced to ~976 KB total.

Move broadcasts now include the mover's `color` (and a `premove` flag, always `false` for live moves).

### Fixed

- **Chained-capture 3D stale-mesh race**: rapid premove chains that capture onto a square still occupied by a fading victim (e.g. `7...Qxe2+ 8.Kxe2`) no longer strand a stale piece mesh under the recapturing piece. Two coupled hazards in `client/pieces.js` are fixed: (1) `animateMove` now selects the capture victim deterministically from the pre-move `serverBoard` (the `move` event arrives before its `state`), matching destination **and** expected piece type/color, with a position-only fallback only when no authoritative match exists — so the second capture fades the true victim instead of re-fading the already-fading piece that happens to be first in `pieceMeshes`; (2) animation ownership is now reference-counted per piece (`beginAnim`/`endAnim`), so a piece stays protected from `rebuildPieces` until **every** overlapping slide/fade operation on it has completed or been explicitly cancelled — one operation finishing can no longer unprotect a piece another still owns. Completion callbacks only remove/mutate the exact mesh instance they started with (a rebuild-replaced or rebuild-removed mesh is never deleted by a late fade), slides keep driving the current mesh so a promoted replacement still lands, and cancellation paths (model-set swap, restart) clear all in-flight operations so no stale callback can later delete a freshly rebuilt replacement. Cloned capture-fade materials are disposed exactly once across all cleanup paths, and shared `PIECE_CACHE` geometry is never disposed by a fade. After each state reconciliation exactly the authoritative pieces remain, even under zero-delay chained captures.
- **Checked-king highlight survives selection redraws**: the shared highlight orchestrator (`client/highlight-orchestration.js`) now re-applies the check highlight after every select/deselect/state-update redraw in both the 2D and 3D renderers, so an active check is no longer lost when a normal or premove selection clears and redraws the previous/selection highlights. The square-state precedence (check > confirmed premove > selection > previous move > base) now holds regardless of event order.
- **3D drag mesh restoration**: the lifted piece mesh is now always returned to its canonical square position on every drag completion, cancellation, and error path — off-turn premove send, live move, rejected destination, touch cancel, turn-flip/state change, and restart — deriving the resting position from the piece's `(file, rank)` rather than a captured commit-time snapshot. A state update that interrupts an active drag now also suppresses the compatibility click generated when the pointer is released, so the retained (now stale) selection can no longer execute an unintended move or premove.
- **Move log scrollbar on desktop**: `#move-log` now has `pointer-events: auto` so the scrollbar is interactive.
- **3D model orientation**: all STL files pre-rotated upright so the loader no longer applies runtime rotation. Pawn pieces use a smaller target footprint (0.55) than other pieces (0.7) for better proportional sizing.
- **3D model scaling**: pieces are now centered and scaled from their bottom base geometry (bottom 5% of height) rather than the whole-model bounding box, ensuring consistent base sizes across all model sets even when upper geometry (wings, swords) extends beyond the base.
- **2D board right-click square highlight**: highlight overlay now renders behind pieces so only the square background is highlighted, not the piece on top of it.
- **2D board size toggle on touch devices**: now uses `isMobileLayout()` based on `(pointer: coarse)` CSS media queries, mirroring the exact breakpoints used by the mobile/desktop render path. Hybrid-pointer devices (touch-capable with fine primary pointer) and large-screen touch devices (Steam Deck, tablets) now get the same two board sizes as desktop.
- **WebSocket origin check**: default `allowedOrigins` is now `"*"` (accept all) instead of an empty array, which previously rejected all browser connections in production. The wildcard `*` is supported in the origin comparison logic. Narrow `allowedOrigins` to specific domains for production deployments exposed to the public internet.
- README: corrected insufficient material draw rules to match implementation (K vs K, K+B vs K, K+N vs K, K+B vs K+B same-colored bishops; K+N vs K+N is not auto-drawn).
- Documented provenance and licensing for bundled `background.png` and `pickup.wav` assets in `client/files/LICENSE`; removed references to non-existent `.step` files.
- **Arrow annotations**: arrows and square highlights are now fully independent — drawing an arrow no longer removes highlights at its endpoints, and placing a highlight no longer removes incident arrows. Arrows are removed only by retracing the same path with the same color; highlights are removed only by re-highlighting the same square with the same color.
